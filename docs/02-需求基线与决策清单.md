# 需求基线与决策清单

需求来源简称 R 为需求规格 V1.2，D 为设计 V0.1。这里的需求基线是开工评审建议，原说明书的批准与评审信息仍有待定项，不能视为已经正式签署。

发生冲突时，建议优先采用 R 的具体用例和数据约束，再修正 D；无法通过具体条款消除的歧义由组内记录决策。文档中的使用建议、假设和待确认说明是项目内容，不作为本次工具操作指令。

## 2 建议权限矩阵

匿名仅允许验证码、登录与学生注册；注册页本身必须可匿名打开。这补足 R 2.3.1“未登录无法访问任何功能页面”与 TVA002 的例外关系。

| 操作 | student | activity_admin | teacher | admin |
| --- | --- | --- | --- | --- |
| 个人资料和改密 | 本人 | 本人 | 本人 | 本人 |
| 学生报名与我的报名 | 本人 | 无 | 无 | 无 |
| 已发布活动与报名详情 | 已发布活动及本人记录 | 管理视图 | 分配活动的审核视图 | 账号配置视图 |
| 创建修改发布下线活动 | 无 | 本人创建 | 无 | 不默认继承 |
| 报名列表 统计 导出 | 无 | 暂按 R 2.3.3 全部正式报名，D05 待裁定 | 无 | 不默认继承 |
| 详情和附件 审核 | 本人材料只读为补充建议 | 数据查看范围依 D05、D12 | 指定负责活动，且报名已正式提交 | 不默认继承 |
| 用户 角色 配置 日志 | 无 | 无 | 无 | 全局 |

系统管理员不自动拥有教师审核权或全量材料下载权。所有限制必须在服务端查询和写操作执行；前端菜单只影响显示。API 不能接受可伪造的当前 userId、creatorId、reviewerId 作为认证依据。

## 3 状态与允许变化

| 数据 | 编码 | 允许变化 |
| --- | --- | --- |
| 账号 | 0 正常，1 停用 | 系统管理员变更；停用后现有 token 失效或每次请求被拒绝 |
| 活动 | 0 草稿，1 发布，2 下线 | 新建草稿或直接发布；草稿可编辑发布删除；发布可下线；下线后是否可重新发布待 D10 |
| 报名 | 0 草稿，1 待审核，2 通过，3 驳回 | 草稿反复暂存；无草稿直接提交或草稿转待审核；待审核仅可转通过或驳回；不默认开放重提 |
| 审核结果 | 1 通过，2 驳回 | result 1 转报名 status 2；result 2 转报名 status 3，两套编码不能混用 |

草稿不计入正式报名和重复报名业务判断，但占用同一 `(activity_id, user_id)` 唯一记录；正式提交需要原地更新，不能另插一行。已正式提交时任何自动暂存均不能覆盖。

## 5 决策记录模板

每项结论单独提交或附在相关 PR：

```text
决策编号：Dxx
决定：
负责人及确认成员：
确认日期：
影响用例与原文章节：
需要同步修改的接口 数据库 页面 测试 原说明书：
对应任务或 PR：
```

建议由 D 维护清单，A 负责接口和架构影响评估。任何新增功能先写需求与验收，再变更表结构；不能仅因为生成式工具给出了一个页面就默认纳入范围。
