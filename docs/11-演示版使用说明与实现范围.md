# 校园活动报名审核系统演示版使用说明

版本 v0.1.0。基于最初需求规格 V1.2、设计说明书 V0.1，并按课程项目的简化要求实现。系统可以在本机完整运行，默认绑定 127.0.0.1。

## 1 直接运行

准备 JDK 17 或更新版本，运行交付包中的启动脚本，或执行：

```powershell
java -jar campus-activity-0.1.0.jar
```

打开 `http://127.0.0.1:8080`。JAR 已包含前端，直接运行时无需安装 Node、Maven 或 MySQL。首次运行在当前目录创建 `data/`，存储内置 H2 数据和上传材料；下次启动继续使用。同一数据目录仅运行一个实例。关闭终端或按 Ctrl+C 停止服务。

| 角色 | 演示账号 | 演示密码 |
| --- | --- | --- |
| 学生 | student1 | Demo1234! |
| 活动管理员 | activity1 | Demo1234! |
| 审核教师 | teacher1 | Demo1234! |
| 系统管理员 | admin1 | Demo1234! |

以上是公开的课程夹具账号，仅适合本机演示。登录页展示图片验证码，需输入后登录。重启服务后，内存token和验证码失效，需要重新登录。

## 2 推荐演示顺序

1. 用 activity1 登录，创建活动，设置报名时间、审核教师和简单表单字段；先保存草稿，再发布。
2. 用 student1 登录，浏览活动，填写表单，可暂存草稿。需要材料的活动上传 jpg、png 或 pdf，再正式提交。
3. 用 teacher1 登录，在审核中心查看报名内容、下载材料，执行通过，或填写原因后驳回。
4. 学生在“我的报名”查看状态与意见；重复报名会被拒绝。
5. 活动管理员在报名数据页查看统计、按活动和提交时间筛选并导出 xlsx。
6. 系统管理员新增教师或学生，修改角色与状态，检查配置和最近操作日志。

个人中心支持姓名、邮箱、手机号和密码修改。改密后当前用户全部token失效。管理员修改账号的密码、角色或状态后，也撤销该账号token。

## 3 从源码构建

要求 JDK 17+、Node 22.x，第一次构建需访问 Maven Central 与 npm。后端自带 Maven Wrapper。

Windows PowerShell：

```powershell
.\scripts\build.ps1
java -jar backend/target/campus-activity-0.1.0.jar
```

macOS/Linux：

```sh
sh scripts/build.sh
java -jar backend/target/campus-activity-0.1.0.jar
```

构建前停止正在运行的本项目后端和Vite开发服务器，避免Windows锁定JAR或esbuild文件。构建过程执行前端生产构建、后端单元/集成测试和JAR打包。GitHub Actions中使用相同流程。若仅开发前端，先启动后端8080，再在frontend目录运行`npm ci`、`npm run dev`。后端端口改变时设置`BACKEND_URL`供Vite代理使用。

## 4 MySQL 模式

内置 H2 为快速演示选择，原设计的 MySQL 模式保留。新建一个空的、独立的 MySQL 8.0.16+ 数据库，创建专用应用账号；应用不能连现有业务库。

```powershell
$env:DB_URL='jdbc:mysql://127.0.0.1:3306/campus_activity?serverTimezone=Asia/Shanghai&characterEncoding=UTF-8'
$env:DB_USER='campus_app'
$env:DB_PASSWORD='本机设置的数据库密码'
$env:INIT_ADMIN_PASSWORD='自行设置至少12字符的管理员密码'
java -jar backend/target/campus-activity-0.1.0.jar --spring.profiles.active=mysql
```

首次启动按`backend/src/main/resources/db/schema-mysql.sql`创建六表，账号默认只创建初始admin，密码取环境变量，不输出到日志。演示专用空库如需生成四角色夹具，可设置`SEED_DEMO=true`，勿对真实数据使用。

已有数据不自动变更表结构；后续字段改动需追加迁移。不要同时执行原准备包V001再误认为应用会自动升级不同结构。当前两者字段保持一致，应用版本另带用于H2和MySQL的初始化脚本。

## 5 当前实现与限制

| 原用例 | 当前实现 |
| --- | --- |
| TVA001 登录 | 图片验证码、四角色、BCrypt、可撤销token、登录时间与IP |
| TVA002 注册 | 用户名与邮箱唯一、密码确认、验证码；服务端强制student |
| TVA003 个人维护 | 资料和密码修改、格式校验、改密失效 |
| TVA004 活动管理 | 草稿增改删、教师指定、发布/下线；发布后冻结字段与教师 |
| TVA005 报名数据 | 统计、活动及提交时间筛选、xlsx导出；列表最近200条，导出分批读取 |
| TVA006 在线报名 | 动态字段、文件校验、30秒草稿、断网本地保留、恢复后同步、唯一报名 |
| TVA007 审核 | 指定教师数据权限、通过/驳回、意见上限、乐观锁与审核记录事务 |
| TVA008 基础管理 | 用户新增修改停用、角色、密码重置、基础配置和最近日志 |
| TVA009 状态查询 | 本人报名、历史意见、本人附件下载 |

简化边界：不实现签到、多级审核、短信或邮件通知、名额抢占、复杂表单拖拽设计器、批量账号导入/导出、用户物理删除、正式报名后补传或驳回重提。账号停用保留历史关联；发布后需要改字段时下线并新建。账号与日志列表限制200/100条，不提供完整后台分页。

草稿保存字段，不保存浏览器已选择的文件；再次进入需重新选择材料。localStorage按用户和活动隔离，退出时清除当前用户缓存；恢复时提示选择本地或服务端草稿，多标签页自动冲突合并未实现。文件扩展名、MIME、头部和大小均检查，材料只能授权下载，但没有引入完整杀毒/内容审查。数据库事务失败会尝试删除新文件，进程崩溃留下的孤儿文件尚需手工维护。

文件上限默认20MiB，配置可调低；请求体上限22MiB。审核意见500个Java字符。导出默认最多50000条，系统可调低，不能调高。活动同名时间冲突检查为普通查询，极端并发创建同名活动未做串行化；正式报名唯一性和审核状态更新有数据库约束。

未进行100请求每秒压测、99.9%长期可用性验证、生产备份自动化或全部旧版浏览器验证。默认本机HTTP，生产HTTPS需另配Nginx与证书。该版本满足课程基本演示，不能直接视为生产部署版本。
