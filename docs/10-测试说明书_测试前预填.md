## 1 引言

### 1.1 编写目的

确定本系统的测试范围、方法、人员和预期结果，指导编码后的单元测试、集成测试与系统测试。按样本保留计划、设计、执行过程与记录结构，简要编写，测试结果以实际执行为准。

### 1.2 测试范围

重点对报名审核构件进行白盒基本路径与黑盒等价类测试；对登录、活动发布、报名、审核、本人状态查询进行系统测试；对报名唯一约束和审核事务进行数据库集成测试。注册、个人资料、草稿、附件、统计导出等第二周完成后补相应用例。

大规模并发、长期 99.9% 可用性和全部浏览器版本的兼容性不纳入本轮实测结论，未测试内容在最终报告列明；不将其写为已经达标。

### 1.3 参考资料

需求规格重点参照 3.3.6 报名、3.3.7 审核、3.3.9 查询、第四章数据表、5.6 并发控制及 7.1 权限；设计重点参照 4.2 审核接口与 5.3.4 审核流程。课程 PPT 要求测试计划、测试设计、测试实施及记录，并形成测试报告。

白盒测试根据源代码结构设计；黑盒测试根据输入输出规格设计；Mock 替代单元测试中的 DAO 依赖；集成测试使用隔离 MySQL 数据库验证实际落库。审核结果 `1/2` 分别为通过/驳回，报名状态 `0/1/2/3` 分别为草稿/待审核/通过/驳回，两组编码不可混用。

## 3 被测构件说明

### 3.1 构件标识

| 项目 | 内容 |
| --- | --- |
| 设计构件 | ReviewController，实现 IReviewController |
| 方法 | submitReview(regId: Integer, result: Char, opinion: String, version: Integer): Boolean |
| 依赖 | IRegistrationDAO、IReviewRecordDAO，当前登录身份与活动教师分配信息 |
| 实现位置 | 开发后填写实际文件、类名与 Git 提交号；若业务放入 Service，保留设计对应关系 |

### 3.2 输入输出规格

| 输入 | 规格 |
| --- | --- |
| regId | 存在的正式报名编号 |
| result | 仅允许字符 `1` 通过或 `2` 驳回 |
| opinion | 最多 500 字符；驳回时去空格后必须非空 |
| version | 与数据库当前版本一致 |
| 隐含条件 | 当前用户为该活动指定教师，报名状态为待审核 |

成功时更新报名状态、版本加一并生成审核记录；失败时提示原因。接口层按统一返回体展示结果。状态更新和审核记录写入必须在同一数据库事务中完成。

### 3.3 处理逻辑

校验参数及驳回原因，检查当前教师权限，按 `regId + version + 待审核状态` 更新报名；影响行数为零时报告已处理；更新成功后写入审核记录并提交。数据库写入异常时事务回滚。

### 3.4 被测源程序

待审核方法实现并固定版本后补入实际代码或代码位置。此处不使用销售系统样本源码，也不将设计流程当作已经实现的源程序。

## 5 黑盒测试设计与集成系统用例

### 5.1 等价类与边界

有效类：合法通过、合法驳回、指定教师、待审核、版本一致。无效类：非法结果、驳回原因空、意见超长、非指定教师、报名不存在、状态已处理或版本不符。意见长度边界为 500 与 501 字符；每条无效用例只改变一个主要条件。

### 5.2 审核构件黑盒用例

默认数据：报名 17 属于活动 101，活动指定教师 2001，报名待审核、version=0；未特别说明时使用合法参数。

| 编号 | 场景与输入 | 预期结果 |
| --- | --- | --- |
| BB01 | 指定教师，result=1，version=0 | 报名变为通过，version=1，新增通过记录 |
| BB02 | 指定教师，result=2，opinion=材料不符合要求 | 报名变为驳回，保存意见，version=1 |
| BB03 | 驳回但意见为空或全空格，分别执行 | 拒绝，不修改状态，不写审核记录 |
| BB04 | result=0、3 或空，分别执行 | 拒绝非法结果，不修改数据 |
| BB05 | 换成非指定教师，其他合法 | 无权限，不修改数据 |
| BB06 | 数据库 version=1，请求 version=0，状态仍待审核 | 返回版本冲突，不覆盖原数据 |
| BB07 | 报名已通过或驳回，使用当前 version，分别执行 | 返回已处理，不新增审核记录 |
| BB08 | regId 为不存在的编号 | 返回记录不存在，不写入数据 |
| BB09 | 合法驳回，意见恰好 500 字符 | 正常保存完整意见 |
| BB10 | 合法驳回，意见为 501 字符 | 拒绝超长意见，不修改数据 |
| BB11 | 审核记录写入抛出异常 | 单元层断言异常处理和失败返回；实际回滚由 IT02 验证 |

表中“分别执行”代表一个用例下的参数变体，执行时可拆为子编号。预期结果是测试设计，不代表已经出现。

### 5.3 集成与系统用例

| 编号 | 测试内容 | 预期结果 |
| --- | --- | --- |
| IT01 | 两个相同 version 的审核请求同时处理同一报名 | 只有一个成功，仅新增一条对应审核记录 |
| IT02 | 状态更新后，模拟审核记录写入失败 | 事务回滚，原状态和 version 不变 |
| ST01 | 四类演示账号登录；错误账号或角色访问审核接口 | 正常账号进入对应入口；错误请求被拒绝 |
| ST02 | 活动管理员发布活动并指定教师 | 学生可看到已发布活动，教师分配正确 |
| ST03 | 学生填写必填项并提交报名 | 数据入库，状态待审核；缺必填项时不提交 |
| ST04 | 同一学生再次报名同一活动 | 重复报名被拦截，数据库只有一条记录 |
| ST05 | 在报名截止时间及之后提交 | 根据约定的截止边界拒绝提交 |
| ST06 | 通过或驳回后，学生查询本人和他人报名 | 本人可见状态与意见；他人记录不可读 |
| ST07 | 第二周附件功能完成后，上传合法文件及超限文件 | jpg/png/pdf 合法文件可用，超过 20MiB 被拦截；文件与请求限制一致 |
