# 接口契约草案

这是从设计 V0.1 4.5 中的路径与控制类操作整理出的可实现草案。接口冻结前需要按 D12、D15、D16、D19 等决策更新。统一响应为 `{success, msg, data, traceId}`；成功时 `msg` 可为空，失败时 `data` 为 null。除登录、注册、验证码外，接口都需要 `Authorization: Bearer <token>`。所有 id 与权限均以服务端会话为准。

## 1 约定

- 时间使用 Asia/Shanghai；API 字符串格式 `yyyy-MM-dd HH:mm:ss`；报名窗口为 `startTime <= now < endTime`。
- 分页请求使用 `page`、`size`，默认 20，最大 100；列表响应使用 `items`、`page`、`size`、`total`。
- `student`、`activity_admin`、`teacher`、`admin` 是唯一角色编码；状态编码沿用需求表 4.7。
- 表单 JSON 以字段 key 存储并校验；服务端根据活动当前 `form_schema` 判断必填、类型、长度、选项与未知字段。
- 文件上传使用 `multipart/form-data`。默认单文件 20 MiB（20971520 字节），类型只允许 jpg/png/pdf，服务端检查扩展名、声明 MIME、文件头和随机存储名。
- 错误码建议：`AUTH_401` 未登录、`AUTH_403` 无权限、`VALIDATION_400` 参数错误、`RESOURCE_404` 不存在、`STATE_409` 状态冲突、`DUPLICATE_409` 重复报名、`CONFLICT_409` 乐观锁冲突、`FILE_413` 文件过大、`FILE_415` 类型不支持、`EXPORT_413` 导出超限、`SERVER_500` 服务错误。

## 2 账户和个人信息

| 方法 | 路径 | 角色 | 请求关键字段 | 成功 data |
| --- | --- | --- | --- | --- |
| GET | `/api/captcha` | 匿名 | 无；响应不暴露答案 | `captchaId`、图片或图片 URL、过期时间 |
| POST | `/api/login` | 匿名 | `account`、`password`、`captchaId`、`captcha` | `userId`、`role`、`token`、`expiresAt` |
| POST | `/api/register` | 匿名学生 | `userName`、`email`、`password`、`confirmPassword`、`captchaId`、`captcha` | `userId` |
| GET | `/api/profile` | 登录用户 | 无 | 脱敏 User DTO，不含密码 |
| PUT | `/api/profile` | 登录用户 | `realName`、`phone`、`email`；改密时 `oldPassword`、`newPassword` | 更新后的脱敏 User DTO |

注册和登录都要在服务端重新校验验证码、唯一性和停用状态。邮箱唯一冲突、密码不一致、验证码失效分别返回可识别错误码。改密成功后当前用户的其他 token 必须失效，具体存储见 D19。

## 3 活动与动态表单

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/activities` | activity_admin | 仅返回当前创建者活动；支持 `status`、分页 |
| GET | `/api/reviewers` | activity_admin | 正常的 teacher 列表 |
| POST | `/api/activities` | activity_admin | `opType` 为 `SAVE_DRAFT`、`PUBLISH`、`OFFLINE`、`DELETE`；服务端检查归属 |
| GET | `/api/published-activities` | student | 仅已发布活动；分页与可选关键词 |
| GET | `/api/activities/{activityId}/detail` | student、活动管理者、指定教师 | 按数据权限返回详情与表单 schema |

建议 `ActivityWriteRequest` 含 `activityId?`、`title`、`content`、`startTime`、`endTime`、`formSchema`、`reviewerId?`、`opType`。`PUBLISH` 必须有正常 teacher、合法时间和可解析 schema。发布后是否冻结字段取 D10；准备包默认冻结。

动态表单字段样例：

```json
{
  "version": 1,
  "fields": [
    {"key":"studentNo","label":"学号","type":"text","required":true,"maxLength":32},
    {"key":"reason","label":"报名理由","type":"textarea","required":true,"maxLength":500},
    {"key":"level","label":"年级","type":"select","required":true,"options":["大一","大二","大三","大四"]}
  ],
  "attachmentRequired": true,
  "attachmentAccept": ["jpg","png","pdf"]
}
```

首版允许类型：`text`、`textarea`、`number`、`select`、`radio`、`checkbox`、`date`。`key` 只允许稳定的字母、数字和下划线；重复 key、未知 type、重复 option 或不合法长度拒绝保存。历史报名展示以提交时保存的 schema 版本为准，若要支持发布后编辑需另建版本表。

## 4 报名和草稿

| 方法 | 路径 | Content-Type | 说明 |
| --- | --- | --- | --- |
| GET | `/api/activities/{activityId}/draft` | JSON | 当前学生本人草稿；无记录返回 data=null |
| POST | `/api/registrations/draft` | JSON | `activityId`、`formData`；点击暂存或每 30 秒调用，不覆盖正式报名 |
| POST | `/api/registrations` | multipart | `activityId`、`formData` JSON、`attachment`；正式提交 |
| GET | `/api/my-registrations` | JSON | 当前学生本人；返回活动摘要、状态、最新审核意见和时间 |

正式提交服务端必须按顺序检查活动存在且已发布、时间窗口、表单 schema、附件、正式重复报名，然后将草稿原地转为待审核或插入待审核记录。并发插入依赖唯一索引并将冲突转为 `DUPLICATE_409`。草稿自动保存失败应保留浏览器 localStorage；恢复时不能自动覆盖服务器上已经正式提交的记录。

`RegistrationSummary` 不返回 `attachmentPath`。详情和附件读取要走教师权限接口；学生只能看到自己的记录。驳回重提路径遵循 D06，默认不开放。

## 5 审核

| 方法 | 路径 | 角色 | 成功 data |
| --- | --- | --- | --- |
| GET | `/api/reviews/pending` | teacher | 分页待审核列表，只含 `activity.reviewer_id = currentUser` |
| GET | `/api/reviews/{regId}` | 指定 teacher | 报名详情、提交时 schema、表单数据和状态；不返回磁盘路径 |
| GET | `/api/reviews/{regId}/attachment` | 指定 teacher | 授权后的文件流，文件不存在返回 `RESOURCE_404` |
| POST | `/api/reviews` | 指定 teacher | `regId`、`result`、`opinion`、`version`；成功返回更新状态和新版本 |

`result=1` 表示通过，变更 registration.status 为 `2`；`result=2` 表示驳回，去空格后 opinion 必须非空，变更为 `3`。SQL 更新条件必须包含 `reg_id`、`version` 和 `status='1'`，影响行数为 0 返回 `CONFLICT_409`。状态更新和审核记录写入一个数据库事务。即使 admin 能查看后台，也不自动取得此审核写权限。

## 6 统计、导入、配置

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/reg-stat` | activity_admin | `activityId?`、`startTime?`、`endTime?`；按 D05 的范围过滤 |
| GET | `/api/reg-export` | activity_admin | 同统计筛选，先 count，超过 50000 返回 `EXPORT_413`；读取和写出都分批 |
| GET | `/api/admin/users` | admin | 分页、角色、状态筛选 |
| POST | `/api/admin/users` | admin | 新增或修改账号；服务端限制高危操作 |
| POST | `/api/admin/users/import` | admin | xlsx；全量校验后再事务写入；错误报告不含密码 |
| GET | `/api/admin/config` | admin | 配置白名单，敏感值脱敏 |
| PUT | `/api/admin/config/{key}` | admin | 仅允许白名单配置键 |
| GET | `/api/admin/logs` | admin | 按时间和操作人查询，按页返回 |

Excel 导出不得把报名表单任意键自动当作不受控列名；应定义固定基础列和经审查的动态字段列。导入模板、列名、错误报告和删除策略在 D17、D14 中确认后再冻结。

## 7 统一错误与安全检查

任何接口都应设置 traceId 并在日志记录请求、角色、业务 id 和结果，不记录密码、token、验证码答案或附件内容。Controller 只做格式和认证上下文，Service 执行角色、数据归属、状态与事务规则；Mapper 参数绑定使用 `#{}`。文件下载使用受控流响应，不能拼接用户提供的磁盘路径。

下面的请求示例是验收最小数据：

```json
POST /api/reviews
{
  "regId": 17,
  "result": "2",
  "opinion": "请补充获奖证明",
  "version": 0
}
```

成功响应的 `data` 至少包含 `regId`、`status`、`version`、`reviewId`。并发第二次请求必须收到 `CONFLICT_409`，不得返回成功。
