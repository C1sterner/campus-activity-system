## 3 交付检查表

- [ ] 需求决策已记录编号、负责人、日期和影响文件。
- [ ] 每个 PR 关联一个用例或缺陷，描述成功与失败路径。
- [ ] 后端所有敏感字段均经过 DTO，密码、token、验证码答案、绝对路径不出现在响应和日志中。
- [ ] 角色校验和数据归属在服务端；学生、教师、管理员交叉越权均有测试。
- [ ] 数据库迁移为追加式；干净库和升级库均能执行。
- [ ] 审核更新、审核记录、唯一报名和草稿提交均有真实 MySQL 集成测试。
- [ ] 文件路径不在 Web 根目录；大小、扩展名、MIME、文件头和异常清理均验证。
- [ ] 导出超过 50000 条、导入错误行、日志写失败、数据库断开均有明确行为。
- [ ] 前端支持失败保留输入、二次确认、空状态、加载状态、断网草稿。
- [ ] 另一位成员从 clean checkout 能复现测试并部署。

## 4 建议提交格式

```text
feat(TVA006): save registration draft
fix(TVA007): reject stale review version
test(TVA006): cover duplicate submit constraint
docs(decision): record D16 time boundary
```

提交正文应说明：改变了什么、对应需求或决策、实际运行命令及结果、是否需要迁移或配置。AI 生成的改动也必须由提交者阅读并对测试结果负责。
