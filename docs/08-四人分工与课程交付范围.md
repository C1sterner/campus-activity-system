# 校园活动报名审核系统四人分工与课程交付范围

编制日期：2026 年 11 月 23 日。适用周期：11 月 23 日至 12 月 13 日。

本轮按本科软件工程课程项目安排：完成可运行、可演示的基本系统，保留代码检查、单元测试、系统测试和完整交付文档。采用一个共享 Git 仓库、一个后端、一个前端和一个 MySQL 库，使用现成 UI 组件，优先完成主流程。

## 1 课程要求与本组完成标准

课程 PPT 明确提出“项目的规模应该适中，功能不宜过多”，同时要求软件编码、代码检查、单元测试、集成构造、可安装或运行的软件、用户手册、测试文档和包含演示的 15 分钟最终报告。评分为课堂参与与评审 20%、项目工作产品 45%、最终报告 35%。

因此本组将“主流程可用、文档与实现一致、测试结果真实、能够清楚演示”作为三周的完成标准。课程 PPT 的第 15 周周二为提交节点；本计划以 12 月 13 日为组内完成日期，课程实际截止日须按校历或教师通知核对，若更早则整体提前。

| 优先级 | 实现内容 | 完成标准 |
| --- | --- | --- |
| 本周必须 | 四角色登录、活动发布、学生报名、教师审核、本人结果查询 | 五步流程连接真实数据库，可完整演示 |
| 第二周补齐 | 简单注册与个人资料、活动编辑下线、基础统计、简单 Excel 导出、简单用户管理 | 九个原用例均有基本实现入口 |
| 第二周按简化方式完成 | 文本与下拉两类动态字段、基础附件上传、草稿暂存与 30 秒自动保存 | 能展示配置、校验、保存和再次进入回显 |
| 第三周必须 | 代码检查、重点构件单元测试、主流程系统测试、打包、使用说明、测试报告、15 分钟 PPT | 他人按说明能启动，文档记录与实测一致 |

批量账号导入、断网后的自动合并、复杂表单设计器和高级配置告警列为本轮拟调整项，不占用本周主流程时间；第二周中期根据进度决定实现或在需求规格与设计中明确删减。签到、多级审核、短信通知、名额抢占、地图地点、封面管理不新增到本轮。保留原说明书版本，另附简短范围变更记录，避免文档声称的功能与成品不一致。

原需求的 100 请求每秒、99.9% 可用性和大规模导出指标不作为本轮计划的实现承诺；如未验证，测试报告如实写“未验证”，同步说明课程演示版的限制。基础权限、防止重复报名、审核状态正确和数据入库仍必须完成。

## 3 建仓库时直接采用的安排

仓库建议名：`campus-activity-system`，私有，四人各用自己的账号。当前本地准备包可作为文档和 SQL 起点，由你选择 GitHub 或 Gitee 创建远程仓库。

```text
frontend/       黄诚负责公共文件与学生页，何云婧负责管理和审核页
backend/        胡云皓负责账户活动模块，徐嘉俊负责报名审核模块
db/             徐嘉俊统一维护，胡云皓协作提供演示数据
docs/           何云婧汇总，四人提交本人模块说明
release/        第三周放运行包、SQL、启动说明和移交清单
```

| 成员 | 功能分支示例 |
| --- | --- |
| 徐嘉俊 | `feat/registration-review` |
| 胡云皓 | `feat/auth-activity` |
| 黄诚 | `feat/student-ui` |
| 何云婧 | `feat/manage-review-ui` |

保持一个 `main` 主分支，每人一个当前功能分支，小步提交；合并前另一名成员看过代码且相关功能能运行即可。本周先用人工构建和检查，不安排搭建复杂 CI。数据库字段和接口变更先在群内同步并更新仓库文档，共同文件由指定负责人合并。

建仓库后的第一批 Issue：初始化工程、账户活动接口、报名审核接口、学生端页面、管理审核页面、首轮联调、测试前说明书。Issue 写清负责人、截止日期和验收结果，具体日程见本周计划书。
