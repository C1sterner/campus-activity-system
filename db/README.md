# 数据库基线使用说明

目标是 MySQL 8.0.16 或更高的 8.0 补丁版本，InnoDB、utf8mb4。CHECK 在 8.0.16 起实际执行。当前机器检测到客户端 8.0.46，但未连接当前服务执行任何 SQL。

先新建隔离开发库，确认选中正确数据库，再顺序执行 V001 和 V002。脚本没有 DROP、TRUNCATE 和删除数据操作；也没有 IF NOT EXISTS，以便在误对已有库重复执行时及时暴露冲突。MySQL DDL 不保证作为一个整体回滚，失败后必须检查已创建的对象，不可直接假定“执行失败即什么都未改”。

字段、类型和枚举来自需求第四章与设计 3.2。增加 CHECK、受限删除的真实外键、update_time 自动更新和配置初值属于准备包实施建议。外键未声明级联删除；被历史数据引用的账号应停用，不应清空历史关联。角色与创建者/教师资格仍由业务层校验，外键不能代替权限检查。

字符排序规则暂定 `utf8mb4_0900_ai_ci`，用户名和邮箱唯一性因此忽略大小写及重音差异；正式冻结时应确认账号规范化策略。配置键统一使用 `upload.max_size_bytes`，相较原文示例 `upload.max_size` 明确了字节单位，前后端与配置后台需同步。

V002 是首次配置种子，只运行一次，不会覆盖已有配置。准备包不含真实账号与密码；首个系统管理员由专用初始化流程生成 BCrypt 哈希，后续账号使用受控后台创建。

上线工程建议接入迁移工具记录 V001/V002 的执行与校验和。已经在共享环境执行的版本不得修改，应追加 V003。SQL 当前只经过静态核对，尚未在独立 MySQL 实例中验证语法、约束和并发行为；这些是 M0 的验收任务。
