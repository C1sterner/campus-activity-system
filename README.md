# 校园活动报名审核系统构建准备包

依据需求规格 V1.2 与设计 V0.1，形成可用于四人小组开工评审的准备材料。建议采用一个共享 Git 仓库，一名成员负责集成，四人分别承担业务、前端、平台与验收职责，每人均可使用 AI。

本目录是构建准备包，尚不包含可运行的完整前后端应用。需求中的九个用例均纳入最终交付；核心流程优先实现。文档差异与新增建议已单独标记，不能视为小组已经批准的需求变更。

## 阅读顺序

1. [构建准备与协作建议](docs/01-构建准备与协作建议.md)：项目判断、技术准备、Git 与 AI 建议、开工门槛。
2. [需求基线与决策清单](docs/02-需求基线与决策清单.md)：范围、权限、状态、文档冲突、需要组内裁定的规则。
3. [接口契约草案](docs/03-接口契约草案.md)：沿用设计路径，补齐请求、响应、数据归属与文件约定。
4. [四人任务与里程碑](docs/04-四人任务与里程碑.md)：任务依赖、负责人角色、可验收产物。
5. [测试与验收计划](docs/05-测试与验收计划.md)：边界、并发、越权、恢复与性能验证。
6. [开发环境检查记录](docs/06-开发环境检查记录.md)：本机实际检查结果与待补项目。

## 可直接复用的工程材料

- `db/mysql/V001__baseline.sql`：六张业务表、外键、唯一索引及校验约束草案。
- `db/mysql/V002__config_defaults.sql`：上传限制等配置初值，不含用户或密码。
- `db/review-transaction.md`：审核原子更新、草稿竞争、重复提交的实现约束。
- `deploy/compose.mysql.yaml`、`deploy/.env.example`：仅数据库的开发环境模板。
- `deploy/nginx.conf.example`：反向代理和上传体积配置片段。
- `scripts/check-env.ps1`：只读环境检查脚本。
- `CONTRIBUTING.md`、`.github/`：分支、评审与任务模板。
- `AGENTS.md`：本项目中使用 AI 的约束。
- `backend/README.md`、`frontend/README.md`：后续代码布局与第一批实现任务。
- `docs/07-来源与准备包校验.md`：来源指纹、已检查项及尚未验证的运行项。

SQL 仅供新建开发库使用。模板不会自动修改当前 MySQL 服务，不要向已有业务库直接执行。Docker 模板需要先安装 Docker 并复制填写环境文件；当前机器尚未验证可运行。

## 立即开始的顺序

1. 召开一次约 30 分钟的开工评审，优先认领决策 D01、D04、D05、D08、D09、D10、D11、D12、D15、D16、D19、D20。
2. A—D 四个职责由成员按实际能力认领，固定一个集成人和一个备份集成人。
3. 选定 GitHub 或 Gitee 的私有仓库，四人各自使用个人账号；将本准备包作为仓库初始内容。
4. 固定 JDK、后端框架、Node 与依赖版本，完成各成员环境检查。
5. 在隔离的 MySQL 8.0 开发库执行 SQL 并验证约束，再推进“发布活动→报名→审核→查询”的第一条完整流程。

准备材料中的“建议默认”用于降低讨论成本。负责人确认后应在决策清单记录日期和结论，再同步修改接口、SQL、测试与原说明书。
